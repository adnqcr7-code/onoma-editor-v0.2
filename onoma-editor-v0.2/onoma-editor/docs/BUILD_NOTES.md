## What was done in this pass

All five priorities from AGENT_PROMPT.md:

1. **dd-block visuals are wired into the render** (was Priority 1).
   New `overlay_renderer.py` renders library SVGs to transparent PNGs
   (cairosvg → PyMuPDF → rsvg-convert, in that fallback order) and
   composites them as timed `overlay` filters in the SAME single-pass
   ffmpeg command as the cuts and captions. Timestamps are remapped
   through the keep-segment math, so a diagram whose span crosses a
   cut stays on screen across the splice instead of blinking.

2. **Ollama/Gemma integration hardened** (was Priority 2).
   New `ollama_client.py` gives both LLM callers one shared wrapper
   with a retry-with-correction loop: when Gemma's output fails
   validation (bad JSON, malformed SVG), it's re-prompted WITH its bad
   answer and the reason it was rejected, up to
   `OLLAMA_MAX_REPAIR_ATTEMPTS` (default 2) times.
   `concept_segmenter.py` gained a deterministic heuristic fallback
   (pause-gap segmentation) for when Ollama is unreachable — the
   pipeline degrades to cruder topic labels instead of losing the
   whole visual stage. Model tags corrected: "Gemma 4 31B" doesn't
   exist; real family is `gemma3:4b/12b/27b` (all vision-capable).

3. **Initial asset library** (was Priority 3). 12 SVGs generated for
   actual_dev-adjacent concepts (neuron, network layers, gradient
   descent, attention, transformer, tokenization, embeddings, API
   cycle, client-server, git branching, recursion stack, binary
   search). Every one passed structural validation + automated visual
   review at display size (2 were regenerated for text-overflow /
   off-palette failures — the review loop works). All are marked
   `status: "candidate"` in index.json. **They await your approval —
   see `ASSET_LIBRARY.md`.**

4. **Karaoke captions** (was Priority 4). `CAPTION_MODE = "karaoke"`
   gives word-by-word highlighting (spoken word flips to
   `CAPTION_HIGHLIGHT_COLOR`, default brand green). Implemented via
   one Dialogue event per word with inline color overrides — works
   everywhere libass runs, no renderer-specific \k tag behavior.
   Chunking is now pause-aware in both modes.

5. **Edge-case hardening** (was Priority 5): the retry loop above,
   fuzzy asset matching (plural variants + difflib similarity with a
   noise floor — "neurons"~"neuron", "sums"~"summation"), and SVG
   structural validation (well-formed XML, viewBox, root element)
   before anything reaches the render.

- **82/82 unit tests pass** (`cd src && python -m pytest ../tests/ -v`),
  including the original 9 command-parser tests — untouched and green.
- **End-to-end render verified with real ffmpeg** (not just the
  synthetic fixture): a 34s 540x960 test video + realistic transcript
  (one cut pair, one dd block with two concepts) went through the
  REAL pipeline in heuristic mode and produced a final mp4 where:
  - output duration 28.53s vs 28.50s predicted (cuts + command-word
    removal are mathematically right)
  - karaoke caption overrides present in the burned-in .ass
  - a vision model confirmed both diagrams appear on screen exactly
    during their concepts' windows (t≈9.6–16.4s and t≈17.5–24.4s)
    and are absent at t=2s and t=27s

  pipeline.py joined the cut filter_complex and the caption chain
  without a `;` chain separator — the "should work end-to-end today"
  render path in AGENT_PROMPT.md would have failed on its first real
  ffmpeg run. Fixed, plus a label-collision fix ([v0] was defined
  twice) and a configurable x264 preset.

## What is NOT verified (assumed / needs your machine)

In rough order of importance:

1. **Real footage through Whisper.** Every test used hand-built
   transcripts. Real speech = real Whisper quirks (punctuation on
   command words is handled; mumbled "cut"s transcribed as "cud" are
   not — that's the false-trigger tradeoff in COMMAND_VOCABULARY.md).
2. **Real Ollama + Gemma segmentation quality.** All LLM tests use
   mocked responses. Whether gemma3:12b draws concept boundaries where
   YOU would is untested — run it standalone on a real dd-block slice:
   `python src/concept_segmenter.py block_slice.json`
3. **Local-Gemma SVG quality.** The candidate library was generated by
   a stronger hosted model (a build-time stand-in for Gemma). Gemma
   12b will produce rougher SVGs; the style guide now contains
   text-fit rules learned from the real failure modes, and the
   validator + retry loop will catch structural garbage, but expect
   visual quality iteration. Constraint respected: the PIPELINE
   remains 100% local; the hosted model only touched build-time
   candidate generation, which you review before use.
4. **Windows.** Everything is PowerShell-safe (subprocess lists, no
   shell strings), and the caption path-escaping handles drive
   letters — but no Windows machine was available. The cairosvg
   Windows DLL situation is the most likely friction point; PyMuPDF
   is the implemented fallback (`OVERLAY_RENDER_BACKEND="pymupdf"`).
5. **Tavily** — still reference-only, needs your API key, unchanged.
